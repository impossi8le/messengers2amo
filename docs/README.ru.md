## Архитектура

**[docs/messenger-platform-architecture.ru.md](messenger-platform-architecture.ru.md)**
Общая архитектура: выбор подхода, компоненты, путь входящего сообщения, путь исходящего и обработка неопределённости, модель данных, безопасность и медиа, развёртывание и ориентиры мощности. Отвечает на вопрос «из чего состоит система и почему именно так».

**[docs/architecture/deployment-and-amocrm-flow.ru.md](architecture/deployment-and-amocrm-flow.ru.md)**
Как сервис размещён и как связан с amoCRM: два разных механизма подключения (REST OAuth и Chats API), путь входящего сообщения от клиента до нативного чата amoCRM, путь ответа менеджера, работа с файлами и существующим архивом, порядок включения пилота. Схемы в mermaid.

**[docs/architecture/vps-inventory-2026-10-21.ru.md](architecture/vps-inventory-2026-10-21.ru.md)**
Фактическая инвентаризация сервера на 21.10.2026: характеристики, занятые порты, список соседних проектов, базовые коды ответов для сравнения после запуска. Отдельный раздел — разбор причины `ERR_CERT_COMMON_NAME_INVALID`: домен попадал в vhost `dzen`, чей сертификат содержит только его имя. Документ фиксирует, что было проверено, а что осталось на момент выкладки.

**[docs/stack-and-parallel-rollout.ru.md](stack-and-parallel-rollout.ru.md)**
Выбранный стек с обоснованием каждой строки и план параллельного запуска рядом с работающим Wazzup. Описывает, что именно придётся разработать, какие доступы нужны и какие ограничения есть по каналам. Важное: параллельный старт не означает двух отправителей на одном номере.

## Проверка статусов

Всё, что можно проверить прямо сейчас, без доступа к чужим системам.

### Живой контур

```bash
curl -s https://messengers.example.com/health/live
curl -s https://messengers.example.com/health/ready
```

- `/health/live` — процесс жив, отвечает `{"status":"ok"}` даже без базы.
- `/health/ready` — готов обслуживать: `{"status":"ready"}` при доступной БД, `503` с `{"status":"unavailable","dependency":"database"}` при отказе.

Контейнеры и порт на сервере:

```bash
docker compose -p messengers2amo ps
ss -lntp | grep 18767
```

Ожидаемо: `api` и `postgres` в статусе `healthy`, единственный опубликованный порт — `127.0.0.1:18767`.

### Тесты

```bash
cd apps/api && npm test && npx tsc --noEmit
cd apps/web && npm test && npm run build
npm --prefix packages/contracts test
npm --prefix packages/observability test
npm --prefix packages/database test
npm --prefix packages/amocrm-protocol test
```

Тестам API нужна PostgreSQL 18:

```bash
docker run -d --name m2a-pg -e POSTGRES_PASSWORD=testpass -e POSTGRES_USER=testuser -e POSTGRES_DB=m2a -p 55440:5432 postgres:18-alpine
```

Адрес по умолчанию: `postgres://testuser:testpass@127.0.0.1:55440/m2a`, переопределяется через `TEST_DATABASE_URL`.

### Состояние интеграции amoCRM

```bash
docker exec messengers2amo-postgres-1 psql -U messengers2amo -d messengers2amo \
  -tAc "select id, state, credential_ref is not null from messengers2amo.crm_accounts"
```

`setup` без токенов — интеграция создана, но владелец ещё не авторизовал её. `active` с токенами — авторизация пройдена.
