# Запрос доступов для запуска шлюза messengers2amo

Документ для передачи ответственному за доступы. Заполненные значения **не** присылать в Git, issue, чат или почту — только в защищённое хранилище/менеджер паролей. Здесь перечислено, что именно требуется и зачем.

Дата: 21.10.2026.

---

## 1. amoCRM — обязательно для live-проверки интеграции

Без этих реквизитов задачи #10–#12 остаются проверенными только на синтетических данных.

| Что нужно | Зачем | Формат |
|---|---|---|
| Домен аккаунта (например `xxxxxxxx.amocrm.ru`) | Адрес REST API и проверка «только ожидаемый домен» | строка |
| `client_id` интеграции | OAuth-обмен кода на токены | строка |
| `client_secret` интеграции | OAuth-обмен и refresh | секрет |
| Redirect URI, зарегистрированный в интеграции | OAuth callback; должен совпадать байт-в-байт | URL |
| Права (scope), выданные интеграции | Проверка достаточности для контактов/сделок/чатов | список |
| Тестовый пользователь amoCRM (логин) | Проверка «автор исходящего сообщения» и прав | учётка |
| Тестовый контакт и тестовая сделка | Сквозной прогон без затрагивания реальных клиентов | ID |
| Номер воронки и ID этапа для теста | Создание сделки в контролируемом месте | числовые ID |

**Отдельно:** регистрация канала Chats API (amojo) — это не то же самое, что OAuth. Нужно подтверждение, что интеграция может быть зарегистрирована как канал чатов, и `amojo_id` аккаунта.

**Важно:** регистрация интеграции и принятие условий amoCRM — действие владельца аккаунта. Автоматически из этого запроса не следует.

## 2. Telegram — для пилота канала

| Что нужно | Зачем |
|---|---|
| Токен **отдельного тестового** бота | Проверка приёма/отправки без риска для рабочего бота |
| Подтверждение, что тестовый бот не используется в рабочем контуре | Исключить конфликт владельцев отправки |
| Решение: Personal / Bot / Business для боевого подключения | Определяет объём адаптера и реалистичность замены |
| Секрет webhook (`secret_token`) | Проверка подлинности входящих |

Тестовый бот не заменяет личный аккаунт менеджера: если рабочий сценарий — переписка с личного номера, это отдельное решение и отдельные ограничения.

## 3. WhatsApp

| Что нужно | Зачем |
|---|---|
| Тип текущего подключения: WABA / QR-привязанное устройство / Coexistence | Определяет, возможен ли официальный серверный адаптер |

| Подтверждение статуса шаблонов (templates) | Отправка вне 24-часового окна |

## 4. MAX

| Что нужно | Зачем |
|---|---|
| Тип аккаунта: обычный рабочий / бот / Open Client | Определяет пригодность серверного шлюза |

## 7. Wazzup
