# Готовность к запуску: что нужно от владельца

Документ для владельца продукта. Отвечает на один вопрос: **что мешает включить продукт прямо сейчас**.
Собран 22.10.2026 на основе `apps/api/src/platform/config.ts` и `ops/deploy/messengers2amo/.env.example`.

Проверить состояние можно командой `npm run readiness` (см. [раздел 4](#4-как-проверить-готовность)).
Значения доступов в этот документ не вписываются — только имена переменных окружения.

Уточнение 26.10.2026: новые обращения по умолчанию в «Неразобранное», без автоматического
назначения; оригиналы файлов в нашем приватном хранилище, вложения в native-чате CRM.
Backup пока на основном VPS; внешний критерий #31 и численные RPO/RTO остаются открытыми.
Живые прогоны и пилот отложены владельцем до завершения разработки и предупреждения
сотрудников. Проверки сервера ниже относятся к 22.10; новые локальные изменения и пределы
их готовности — в `docs/acceptance/2026-10-26-board-runtime.ru.md`.

## 1. Что нужно от владельца

Ниже — сгруппировано по каналам. Для каждого пункта: зачем, в каком виде предоставить и какая переменная окружения это включает.

### 1.1 amoCRM — основное рабочее место менеджера

| Что нужно | Зачем | В каком виде | Переменные |
|---|---|---|---|
| Интеграция OAuth в аккаунте amoCRM | Без неё нет синхронизации контактов, сделок и нативных чатов CRM | `client_id`, `client_secret` из настроек интеграции | `AMOCRM_CLIENT_ID`, `AMOCRM_CLIENT_SECRET` |
| Публичный HTTPS-callback | amoCRM возвращает на него код авторизации | Полный URL вида `https://<домен>/<путь>` | `AMOCRM_REDIRECT_URI` |
| Поддомен аккаунта | Адрес API аккаунта | Только поддомен, без `.amocrm.ru` | `AMOCRM_ACCOUNT_DOMAIN` |
| Ключ шифрования токенов | Токены OAuth хранятся в базе зашифрованными | Сгенерировать на сервере: `openssl rand -hex 32` | `AMOCRM_TOKEN_KEY` |
| Подтверждение доступа в браузере | OAuth требует нажатия «Разрешить» владельцем аккаунта | Одно действие в браузере по ссылке авторизации | — |

**Важно:** само нажатие «Разрешить» делает владелец аккаунта. Разработчик этого сделать не может.

### 1.2 Telegram — основной канал приёма сообщений

| Что нужно | Зачем | В каком виде | Переменные |
|---|---|---|---|
| Бот и его токен | Приём и отправка сообщений в Telegram | Токен от `@BotFather` | `TELEGRAM_BOT_TOKEN` |
| Секрет webhook | Проверка, что входящий запрос пришёл действительно от Telegram | Случайная строка; она же передаётся при установке webhook | `TELEGRAM_WEBHOOK_SECRET` |

### 1.3 WhatsApp Cloud API

| Что нужно | Зачем | В каком виде | Переменные |
|---|---|---|---|
| App secret приложения Meta | Проверка подписи `X-Hub-Signature-256` входящих событий | Значение из настроек приложения Meta | `WHATSAPP_APP_SECRET` |
| Access token | Отправка исходящих сообщений | Системный токен пользователя | `WHATSAPP_ACCESS_TOKEN` |
| Phone number id | Идентификатор номера в WhatsApp Business | Числовой id номера | `WHATSAPP_PHONE_NUMBER_ID` |
| Verify token | Ответ на GET-проверку подписки на webhook | Случайная строка, задаётся и в Meta, и у нас | `WHATSAPP_VERIFY_TOKEN` |

Канал включается только когда заданы `app_secret`, `access_token` и `phone_number_id` одновременно. Частичная настройка не регистрирует маршрут.

### 1.4 MAX

| Что нужно | Зачем | В каком виде | Переменные |
|---|---|---|---|
| Токен бота | Отправка сообщений в MAX | Токен из кабинета MAX | `MAX_ACCESS_TOKEN` |
| Секрет webhook | Проверка заголовка `X-Max-Bot-Api-Secret` | Случайная строка | `MAX_WEBHOOK_SECRET` |

### 1.5 VK — сообщения сообщества

| Что нужно | Зачем | В каком виде | Переменные |
|---|---|---|---|
| Числовой id сообщества | Адресация Callback API | Число | `VK_GROUP_ID` |
| Токен доступа сообщества | Отправка сообщений | Токен из настроек сообщества | `VK_ACCESS_TOKEN` |
| Секрет Callback API | Проверка каждого входящего события | Значение из настроек Callback API | `VK_SECRET` |
| Код подтверждения | Ответ на GET-проверку `type=confirmation` | Строка из настроек Callback API | `VK_CONFIRMATION_CODE` |

### 1.6 S3 / медиа

| Что нужно | Зачем | В каком виде | Переменные |
|---|---|---|---|
| S3-совместимый бакет для вложений | Без него файлы живут в памяти процесса и исчезают при перезапуске | `endpoint`, имя бакета | `S3_BUCKET`, `S3_ENDPOINT`, `S3_REGION` |
| Ключ, ограниченный этим бакетом | Доступ к объектам | `access_key`, `secret_key` | `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` |

Ключ должен быть выдан именно на этот бакет: префикс папки границей доступа не является.

### 1.7 Сервер, домен и бэкапы

| Что нужно | Зачем | В каком виде | Переменные |
|---|---|---|---|
| Подтверждение владения доменом | HTTPS-вход и OAuth-callback работают только на нашем домене | Подтверждение, что домен остаётся за нами | — |
| Внешнее хранение резервных копий — пока отложено | Критерий #31 остаётся открытым; владелец выбрал временно основной VPS | Сейчас `/opt/messengers2amo/backups`; отдельный ресурс позже | — |
| Токен для `/metrics` | Метрики и алерты без защиты не включаются | Сгенерировать: `openssl rand -hex 24` | `METRICS_TOKEN` |

## 2. Что уже готово и не требует действий владельца

- Сервис развёрнут и отвечает на `GET /health/live` и `GET /health/ready` кодом 200.
- Приём сообщений Telegram проверен на реальном боте: webhook установлен, подпись проверяется, запросы без секрета отклоняются.
- Схема и runner с журналом `schema_migrations` готовы; в текущей локальной ветке нужны
  версии 1–17. Применённость на production после изменений 26.10 здесь не подтверждается.
- Аутентификация сотрудников, сессии, роли, мастерские, назначение обращений — реализованы и покрыты тестами.
- Обработка вложений, защита от SSRF, проверка типов файлов — реализованы.
- Бэкап, восстановление и откат отрепетированы; метрики и правила алертов подготовлены.
- Модуль самопроверки готовности и команда `npm run readiness` — этот документ описывает их вывод.

## 3. Что произойдёт, если доступ не выдан

| Без чего | Что останется выключено |
|---|---|
| amoCRM | Чаты принимаются, обрабатываются и на них можно ответить, но синхронизации контактов, сделок и нативных чатов CRM не будет. Это блокер для полноценного продукта. |
| Telegram | Не работает основной канал: сообщения не принимаются и не отправляются. Это блокер запуска. |
| WhatsApp Cloud | Канал WhatsApp выключен; остальные каналы работают. Предупреждение. |
| MAX | Канал MAX выключен. Предупреждение. |
| VK | Канал VK выключен. Предупреждение. |
| S3 | Вложения хранятся в памяти процесса и теряются при перезапуске. Предупреждение: для production не годится. |
| `METRICS_TOKEN` | Маршрут `/metrics` отвечает 404; мониторинга и алертов нет. Предупреждение. |

## 4. Как проверить готовность

```bash
cd apps/api
npm run readiness
```

Команда читает конфигурацию, при доступной базе сверяет журнал миграций и печатает отчёт на русском.
Код завершения: `1` — есть блокеры, `0` — блокеров нет.

Отчёт делится на три раздела:

- **БЛОКЕРЫ** — без них запускаться нельзя. Сюда попадают: нет строки подключения к базе, база недоступна, применены не все миграции (с перечнем отсутствующих версий), нет или слишком короткий `SESSION_SECRET`, нет токена или секрета webhook Telegram, нет доступов amoCRM (внешний блокер владельца).
- **ПРЕДУПРЕЖДЕНИЯ** — запуск возможен, но часть функций выключена: не настроены WhatsApp, MAX, VK, S3 (медиа в памяти) или `METRICS_TOKEN`.
- **НЕОБЯЗАТЕЛЬНОЕ** — на запуск не влияет: например, закрытый исходящий шлюз `OUTBOUND_ENABLED` до прохождения smoke-проверок.

Если база недоступна, команда не падает: это фиксируется как блокер `database_unreachable`.
Значения секретов в отчёт не попадают — только имена переменных, которые нужно задать.
