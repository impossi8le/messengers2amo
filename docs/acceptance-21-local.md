# Приёмка #21: локальная нагрузка и доступность

Дата: 22.10.2026. Статус: **выполнено для локальной части**. Живые каналы, amoCRM и восстановление вне VPS в этот документ не входят — они требуют доступов владельца.

## Что проверялось

Два пункта приёмки #21, которые не требуют внешних доступов:

1. **Нагрузка** — поведение шлюза под конкурентной нагрузкой и сохранение инвариантов.
2. **Доступность** — соответствие интерфейса базовым требованиям WCAG AA на уровне разметки и контраста.

## 1. Нагрузка

Прогон: `cd apps/api && node --test --test-concurrency=1 test/load/*.test.ts` — 3 файла, все прошли.

**Профиль машины:** Intel Core i5-12400F (12 потоков), 34 ГБ RAM, Windows 10 (10.0.19045), Node v24.20.0, PostgreSQL 18.6 на localhost. Машина разработчика, не выделенный стенд.

| Сценарий | Факт | Бюджет | Запас |
|---|---|---|---|
| ingest: 500 webhook, 25 параллельно | p95 **67.4 мс**, p99 73.7 мс, max 84.9 мс, 691.6 соб./с | p95 ≤ 500 мс | 7.4× |
| send: 100 команд, 8 воркеров | p95 **101.8 мс**, p99 135.2 мс, max 142.0 мс, 264.2 ком./с | общее ≤ 15 с | 0.48 с |
| operator: 200 запросов, 200 сессий | p95 **433.2 мс**, p99 453.2 мс, max 458.3 мс, 420.3 зап./с | p95 ≤ 750 мс | 1.7× |

Состояние под нагрузкой: `http5xx=0`, `requestFailures=0`, пик ожидания пула 190, после прогона `waiting=0`, `total=10`, `idle=10`.

**Инварианты, которые проверяются assertions:**

| Инвариант | Что означает падение |
|---|---|
| Ровно одна обработка события | Одно и то же входящее применилось дважды — дубль обращения или сообщения |
| Отсутствие дублей по ключу | Повторная доставка создала вторую запись вместо ACK |
| Fence воркеров | Два воркера отправили одну команду — двойное сообщение клиенту |
| Нет 5xx и утечек пула | Отказ под нагрузкой либо соединения не возвращаются в пул |

**Что не доказано:** реальный сетевой транспорт провайдеров (используются fake-транспорты), несколько инстансов API на одной базе, деградация при нехватке диска или памяти. Для этого нужен отдельный стенд.

## 2. Доступность

Тесты: `apps/web/src/a11y/screens.test.tsx` (8) и `apps/web/src/a11y/contrast.test.tsx` (24). Оба файла в общем прогоне.

**Разметка и клавиатура** — семь экранов (очередь, карточка диалога, подключения, мастерские, CRM, сотрудники, диагностика):

- один landmark `main`, один banner вне `main`, один `contentinfo`;
- навигация имеет доступное имя «Основная навигация»;
- ровно один `h1` внутри `main`;
- порядок заголовков без пропуска уровней;
- у каждого интерактивного элемента (кнопка, ссылка, поле, список, переключатель) есть доступное имя;
- переход по Tab и Shift+Tab идёт в осмысленном порядке.

**Контраст** — 12 пар цветовых токенов в обеих темах, порог 4.5:1 (WCAG AA для обычного текста). Проверяются скомпилированные значения из `src/styles/global.scss`, а не вычисленные стили jsdom: jsdom не умеет считать раскладку и краску, поэтому проверка идёт по фактическим значениям токенов.

**Найдено и исправлено:** кнопки смены статуса сотрудника имели одинаковое доступное имя «Сменить»; теперь имя содержит сотрудника, и скринридер различает их.

**Ограничение метода:** проверка идёт в jsdom без движка раскладки и без настоящего браузера. Это ловит ошибки разметки, имён и контраста токенов, но не проверяет реальный фокус-ринг, порядок в модальных окнах и поведение с конкретным скринридером. Для этого нужен браузерный прогон с axe и ручная проверка скринридером.

## Итог

Локальная часть приёмки #21 закрыта: нагрузочные инварианты подтверждены с большим запасом, доступность проверена воспроизводимыми тестами. Остаются live-сценарии (14 из 45), сквозной прогон с реальными каналами и amoCRM, восстановление вне VPS — всё это требует владельца.
