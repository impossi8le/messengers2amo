# Пилот создания заявки через Messengers2amo

Владелец разрешил тест: новое сообщение тестовому Telegram-боту принимает наш шлюз
и создаёт заявку в «Печать на холсте П14» (воронка 10007030), «Неразобранное».

Это отдельный ограниченный этап приёмки. До регистрации Chats API переписка
остаётся в нашей админке; нативный чат amoCRM не считается подключённым.
Для создания заявки используется REST API неразобранного категории `forms`,
с явно указанным источником «Messengers2amo · Telegram». Категория `chats`
появится после настоящего подключения Chats API.

## Включение

Только worker читает пару переменных `AMOCRM_LEAD_CAPTURE_COMPANY_ID` и
`AMOCRM_LEAD_CAPTURE_CONNECTION_ID`. Обе обязательны для включения режима;
без них действует прежний путь через Chats API. Выбор проверяется по компании
и реальной связи диалога с подключением в БД. Маршрут подключения определяет
аккаунт, воронку и статус; отсутствие маршрута не подменяется воронкой по умолчанию.

При пустом статусе создаётся неразобранное без явного назначения ответственного;
при заданном статусе создаётся обычная сделка. Контакт и сделка защищены
существующими долговечными намерениями создания. Неопределённый результат
не повторяется автоматически. Повторные сообщения того же диалога используют
ту же заявку. Медиавложения и двусторонний нативный чат этим этапом не проверяются.

Исходящие Telegram-сообщения блокируются `OUTBOUND_ENABLED=false` до захвата
заданий worker. Для пилотного подключения также выключена отправка на уровне БД.
Старые сообщения не переотправляются в CRM: задания создаются при получении
новых сообщений после включения политики.

## Ограничение перехода на нативный чат

Перед выключением режима capture нужно отдельно согласовать обработку созданной
тестовой заявки и её привязку к чату. Заявка категории forms сама не становится
чатом. Автоматическую миграцию пилотной заявки этот режим не обещает.

Живая проверка нового сообщения и результат выкладки записываются после получения
сообщения от владельца; предварительные тесты не доказывают принятие запроса amoCRM.

## Проверка готовности обмена текстом и картинками в обе стороны

По следующему запросу владельца проверен именно путь Telegram ↔ штатный чат amoCRM.
Сквозной тест **не пройден**; успешное создание заявки категории forms его не заменяет.

Текущее состояние прода после поступления нового вложения:

- `amocrm_channels` пуст: наш нативный канал Chats API не зарегистрирован/не подключён.
- `S3_BUCKET` не настроен; worker не запускает файловый архиватор.
- В очереди есть одно `telegram.media` в pending и одно новое `amocrm.projection`
  в failed. Старое текстовое задание остаётся completed.

  (`crm_media_storage_unavailable`). Эта ошибка обнаружена живым вложением.

  `sendDocument` отсутствуют. `amocrm/replies.ts` принимает только текстовые
