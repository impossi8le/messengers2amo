# Живой приём Telegram без CRM — 27.10.2026

Владелец разрешил отправить собственное текстовое сообщение в тестового бота и проверить
его приём. Передача в CRM, ответы и тестовые записи в CRM пока запрещены; их нужно
отдельно согласовать после предупреждения сотрудников.

## Ограничение внешних эффектов

Перед тестом подтверждены `OUTBOUND_ENABLED=false` и остановленный worker. Для единственного
тестового Telegram Bot-подключения явно установлено `crm_projection_enabled=false`.
Функция `channel_crm_import_allowed` вернула false. Изменение записано в аудит как
`channel.inbound_test_isolated`, диагностический код `crm_projection_disabled`.
Прежняя политика и исходные счётчики сохранены в закрытом rollback-каталоге релиза.
Приём входящих оставлен включённым. Webhook и секреты не менялись.

## Фактический результат

Владелец вручную отправил текст «Тестовое сообщение для тебя 1234 DD ff».
Входящее принято **27.10.2026 в 11:41:57 по Москве**. В авторизованной production-админке
открыт диалог: виден полный совпадающий текст, один новый вопрос, ожидающий ответа.
Сообщение показано один раз. Никакие кнопки отправки/назначения/закрытия не нажимались.

## Граница приёмки

Принят только путь **реальное текстовое сообщение Telegram → webhook → inbox → история
и ожидание ответа → отображение в нашей админке**. Проверка не доказывает приём файлов,
редактирования/удаления, восстановления после сетевого сбоя, ответов и native amoCRM.
RT08 остаётся открытой: Chats API, контакты по телефону и CRM-записи в этот тест не входили.
Разрешения на дальнейшую CRM-проекцию, пилот или переключение из этого результата нет.
