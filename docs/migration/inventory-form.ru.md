# Форма инвентаризации подключений

Задача: [#17](https://github.com/lenremont2/analog_whatsapp-for-amocrm/issues/17). Дата: 21.10.2026.

Эта форма заполняется **один раз**. Она нужна, чтобы понять, как сейчас устроены рабочие каналы связи, и подготовить переключение на новый контур без отключения Wazzup. Заполнение занимает 15–20 минут. Ничего менять в Wazzup, amoCRM, на телефонах или в сообществах во время заполнения не нужно.

Доступ к кабинету Wazzup пока не выдан, поэтому форма собирает то, что знает владелец. То, что можно проверить только в кабинете, будет сверено позже — отдельно и без изменения текущих настроек.

## Как заполнять

- Пишите обычными словами. Если не знаете ответ — пишите **«не знаю»**, это нормальный и полезный ответ. Не угадывайте.
- **Не присылайте** пароли, токены, коды из SMS, номера телефонов, ссылки с секретными ключами и переписки. Для этого есть защищённое хранилище. В форме достаточно словесного описания.
- Одна карточка — **одно реальное подключение**: один номер, один бот или одно сообщество. Если номеров/ботов несколько, скопируйте блок нужного канала и заполните ещё раз.
- Если канал не используется, отметьте «не используется» и переходите к следующему.
- Заполненную форму верните ответственному за миграцию в защищённом канале. **Не коммитьте заполненную форму в Git**: в ней могут быть имена и названия. Ответственный перенесёт ответы в обезличенный реестр и задаст только те вопросы, которые остались без ответа.

**Ориентир по времени:** общая часть — 3 минуты, каждый используемый канал — 2–3 минуты, подтверждение — 2 минуты. Неиспользуемый канал заполняется одной отметкой.

## Что будет дальше

1. Ответы переносятся в обезличенный реестр `docs/migration/inventory.ru.md`. Реальные номера, имена клиентов и доступы в репозиторий не попадают.
2. Для каждого канала проверяется, что у него один владелец получения сообщений и один владелец отправки. Опасные комбинации фиксируются до переключения.
3. Если чего-то не хватает, ответственный задаст точечный вопрос — заново всю форму заполнять не нужно.
4. Переключение начинается только после отдельного решения владельца и проверки по `docs/migration/cutover-readiness.ru.md`. До этого Wazzup продолжает работать как обычно.

## Служебное соответствие (заполняет ответственный за миграцию)

Не заполняется владельцем. Нужно, чтобы из ответов получить поля программной модели `apps/api/src/migration/inventory.ts`.

| Поле реестра | Откуда берётся в форме |
|---|---|
| `alias` | Псевдоним, назначает ответственный (например `WA-PROD-01`) |
| `channel` | Часть 1–4, название канала |
| `mode` | Вопрос «как подключён»: QR/официально/бот/обычный аккаунт/сообщество |
| `environment` | `production`, если канал используется; `test` для тестового актива |
| `active` | Вопрос «канал используется сейчас?» |
| `assetAlias` | Псевдоним номера/бота/сообщества; один и тот же для всех подключений одного актива |
| `owner` | Вопрос «чей номер/аккаунт/сообщество» + «кто администратор» |
| `inbound.transport` | Вопрос «куда приходят сообщения» и подсказки о способе доставки |
| `inbound.subscriber` | Система, которая принимает сообщения (Wazzup, новый контур, телефон) |
| `outbound.owner` | Вопрос «кто отправляет» и «есть ли другие сервисы/автоматизации» |
| `capabilities.groups/files/templates/outboundInitiated` | Часть «что используется из функций» |
| `crmProjection.owner` | Общая часть: где ведётся список клиентов/сделок |
| `historyExport` | Вопрос «нужна ли история и есть ли способ выгрузить» |
