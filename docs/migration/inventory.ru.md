# Инвентаризация подключений перед заменой Wazzup

Задача: [#17](https://github.com/lenremont2/analog_whatsapp-for-amocrm/issues/17). Состояние на 21.10.2026: подготовлен реестр и процедура; фактическая инвентаризация production **не выполнена**. Рабочие подключения менять по этому документу пока нельзя.

Обновление 22.10.2026: новый контур развёрнут в production (HTTPS, health/readiness), но
доступ к Wazzup/amoCRM для обследования по-прежнему не выдан. Инвентаризация production-
подключений не выполнялась, статусы строк реестра ниже (`UNKNOWN` / «Не получено») не менялись.
Программная модель реестра и проверки покрыты автотестами (`apps/api/test/migration-inventory.test.ts`),
что не заменяет обследование реальных подключений.

- Форма для владельца (заполняется за 15–20 минут): `docs/migration/inventory-form.ru.md`.
- Критерии готовности канала к переключению: `docs/migration/cutover-readiness.ru.md`.
- Программная модель реестра и автоматические проверки: `apps/api/src/migration/inventory.ts`.

## Подтвержденные факты и границы

- Пользователь подтвердил amoCRM и наличие WhatsApp, Telegram, VK и MAX в используемом наборе каналов. Активность каждого подключения, точное количество аккаунтов и режимы не обследованы.
- Проверен отдельный локальный Telegram Bot API прототип: входящие от двух тестовых аккаунтов разделены, ответ через интерфейс доставляется. Это не проверка подключения рабочего Telegram из Wazzup, переноса истории или amoCRM.
- Доступ к настройкам Wazzup, amoCRM и владельцам рабочих аккаунтов для этой инвентаризации не предоставлен. Неизвестное ниже нельзя трактовать как отсутствие функции.
- Ключи, QR-сессии, телефоны, имена клиентов, chat IDs и переписки в Git и issue не сохраняются. В реестре используются псевдонимы; реальные идентификаторы и доказательства размещаются в защищенном хранилище компании с ограниченным доступом. В Git допустим только непривилегированный reference на запись, без секретных URL.

## Карточка подключения: заполняется для каждой строки production

| Поле | Заполнить / проверить |
|---|---|
| Псевдоним, среда, активность, дата проверки | `UNKNOWN` до подтверждения |
| Человек — владелец канала; администраторы Wazzup и amoCRM | Назначить; не подменять владельца названием сервиса |
| Режим и версия API / партнер | Значение и подтверждение из настроек; не определять режим только по наличию QR |
| Права, владение активами, доступ к восстановлению | Только наличие/срок/ответственный, без значений ключей |
| Входящий маршрут и его владелец | Webhook/подписка/polling, кто может изменить, как остановить и восстановить; реальный адрес хранить вне Git |
| Все исходящие отправители | Wazzup, amoCRM-автоматы, боты, люди, сторонние интеграторы; включая отложенные очереди |
| Все создатели CRM-сущностей и сообщений | Канал Chats, REST/webhook-обработчики, правила поиска контакта/сделки, автоматизации |
| Источник истины по видам данных | Транспортные события/статусы, CRM bindings, история, медиа, назначения, неотвеченные обращения: для каждого — владелец и механизм сверки |
| План нового ingestion ownership | Один подтвержденный владелец; shadow feed только после проверки допустимости и отсутствия влияния на действующий маршрут |
| План egress fence | Запрет отправки и CRM-эффектов на новом контуре по умолчанию; отдельное подтверждение остановки старых отправителей. Lease нового worker не ограждает Wazzup |
| Незавершенные действия | Pending / in-flight / unknown; порядок сверки и ручного разбора неизвестного результата; запрет слепого повтора |
| История и файлы | Что доступно для экспорта, идентификаторы и связи, сохранность самих файлов, срок доступности старых URL/чата после отключения |
| Ограничения и цена миграции | Окна отправки, шаблоны, лимиты, возможный перерыв, права, действия партнера, длительность обратного перехода; только подтвержденные данные |
| Контрольная точка и сверка | Время/курсор, счетчики событий и открытых обращений, переходный интервал, способ разбора дублей без общих IDs |
| Критерии переключения / остановки | Измеримые пороги, интервал наблюдения и ответственный решения; значения согласовать до rehearsal |
| Возврат | Точная проверенная процедура, сохраняемые состояния, права и допустимое время; если возврат не доказан — производственное переключение запрещено |
| Доказательства | Защищенные ссылки, дата, проверяющий; в issue только обезличенный итог |

## Проверки по каналам

| Канал | Что определить до выбора адаптера | Переносимые данные — предмет проверки | Ограничение получения и возврата |
|---|---|---|---|
| WhatsApp | Тип подключения, владение номером и бизнес-активами, партнер, права на миграцию, требования конкретного API и порядок восстановления | История/медиа/контакты/CRM-связи отдельно; импорт истории не считать новыми live-событиями | Coexistence не доказывает возможность двух CRM-интеграторов. Обратный перенос и сроки подтверждаются для этого номера; отдельный тестовый номер первым |
| Telegram | Personal, Bot API или Business; кто владеет учетной записью/ботом и текущим webhook/polling | Только доступные выбранному режиму данные; Bot API не обеспечивает перенос всей личной истории | У Bot API проверять единственного получателя; не запускать конкурирующий polling и не заменять рабочий webhook для теста. Возврат маршрута проверять на тестовом боте |
| VK | Реальный тип подключения, сообщество, права, Callback/Long Poll, действующие серверы и автоматы | Диалоги/медиа/CRM bindings в пределах разрешенного API и реальных доступов | Не предполагать эксклюзивность или безопасность дополнительного callback: проверить доставку/дубли и всех отправителей; восстановление конфигурации отрепетировать |
| MAX | Тип аккаунта/бота, доступ организации, используемый API, подписки и способы получения | Только подтвержденные выбранным API история/вложения/связи | До актуальной проверки режима не обещать личный аккаунт, импорт истории или параллельные подписки. Возврат — только по подтвержденному способу подключения |

## Порядок фактического обследования

1. Назначить ответственных людей и открыть настройки в режиме чтения. Не менять подписки, токены, режимы и текущие автоматы.
2. Сверить список в Wazzup со списком каналов/интеграций и активных автоматизаций amoCRM; добавить строку на каждый обнаруженный аккаунт. Зафиксировать расхождения, не предполагать, что список пользователя исчерпывающий.
3. Для каждой строки получить карточку у владельца платформы/аккаунта; подтвердить режим по настройкам и первичной документации. Не копировать секреты в артефакты.
4. С согласованного тестового контакта проследить входящий, создание/связь сущностей CRM и ответ по действующему маршруту. Зафиксировать обезличенные счетчики, время и наблюдаемые статусы. Не отправлять сообщения реальным клиентам ради проверки.
5. Проверить экспорт на небольшой согласованной тестовой выборке: события, связи и открываемые файлы. Проверить, что ссылки не являются единственным способом сохранить нужные медиа. Документировать неподдерживаемое.
6. Сопоставить все отправители/CRM-проекторы с механизмами остановки. Сверить отложенные очереди и действия с неопределенным исходом; назначить владельца ручного разбора.
7. Выполнить rehearsal по `ops/runbooks/channel-cutover.ru.md` на отдельном тестовом подключении. По каждому не пройденному пункту записать блокер. Рабочее подключение не переключать до подтверждения возврата.
8. Ответственный за эксплуатацию и владелец канала подтверждают реестр, evidence и пороги. В #17 приложить обезличенный отчет, что реально проверено и что остается неизвестным.

## Условия завершения #17

- Все фактические подключения учтены и сверены с Wazzup/amoCRM; для критичных полей нет `UNKNOWN`.
- Для каждого определены владельцы получения, всех исходящих и CRM-проекции, источники истины, переносимость данных и способ ограждения эффектов.
- Есть доказательства сверки и тестовой репетиции восстановления; установлены критерии готовности/отката.
- Секреты и клиентские данные остаются вне Git/issue. Незакрытые ограничения отражены в плане каналов и последующих задачах.

Сейчас эти условия не выполнены. Следующие входные данные: доступ администратора на чтение к Wazzup/amoCRM, владельцы каналов, фактические режимы/количество подключений и отдельные тестовые активы для rehearsal. Этот документ не дает права менять production.
