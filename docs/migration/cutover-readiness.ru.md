# Критерии готовности к переключению канала

Задача: [#17](https://github.com/lenremont2/analog_whatsapp-for-amocrm/issues/17). Дата: 21.10.2026.

Документ задаёт **условия допуска** к переключению одного канала с Wazzup на новый контур. Это шаблон: он не подтверждает готовность сам по себе и не является отчётом о проверке. Переключение без заполненного решения о готовности запрещено.

Связанные документы:

- `docs/migration/inventory-form.ru.md` — форма для владельца, из которой собирается реестр.
- `docs/migration/inventory.ru.md` — обезличенный реестр и правила обследования.
- `docs/migration/parallel-pilot.ru.md` — наблюдательный пилот рядом с Wazzup.
- `ops/runbooks/channel-cutover.ru.md` — процедура переключения и возврата.

## Как пользоваться

1. Для каждого канала заполняется отдельный экземпляр этого документа (или отдельный раздел решения).
2. Каждый критерий получает статус: `PASS`, `FAIL`, `NOT RUN` или `NOT APPLICABLE`. `NOT RUN` не равен `PASS`.
3. У каждого критерия есть доказательство. Доказательство хранится в защищённом хранилище; в Git и issue попадает только обезличенная ссылка и дата.
4. Канал получает `GO` только если **все обязательные критерии** имеют `PASS`, подписи собраны, а стоп-условия не сработали.
5. Любой участник может объявить `STOP`. Это не удаление данных и не «откат любой ценой»: сначала прекращаются новые эффекты, сохраняется состояние, затем принимается решение по процедуре возврата.

## Статусы и подписанты

| Статус | Значение |
|---|---|
| `PASS` | Проверено, доказательство приложено, ответственный подтвердил |
| `FAIL` | Проверено, условие не выполнено; переключение запрещено |
| `NOT RUN` | Не проверялось; считается блокером |
| `NOT APPLICABLE` | Не относится к этому каналу; обоснование обязательно |

| Роль | За что подписывает |
|---|---|
| Владелец канала (бизнес) | Что канал действительно нужен, владелец аккаунта/номера/сообщества подтверждён, бизнес-риск принят |
| Ответственный за эксплуатацию | Что мониторинг, дежурство, окно и процедура возврата обеспечены |
| Технический руководитель миграции | Что реестр, проверки, пилот и репетиция возврата выполнены |
| Владелец CRM (amoCRM) | Что связи контактов/сделок и правила создания сущностей проверены |
| Владелец компании или уполномоченное лицо | Итоговое `GO` и дата переключения |

Один человек может совмещать роли только письменным решением владельца компании. Отсутствие подписи — блокер, а не «согласие по умолчанию».

## Часть A. Общие критерии для любого канала

Эти критерии обязательны для Telegram, WhatsApp, MAX и VK. Канальные дополнения — в части B.

G1–G3 дополнительно проверяются программно: `validateStoredInventory()` из `apps/api/src/migration/inventory.ts` должен вернуть пустой список ошибок. Коды `DUPLICATE_OUTBOUND_OWNER`, `CONFLICTING_INBOUND_SUBSCRIBER` и `WEBHOOK_POLLING_CONFLICT` — автоматический блокер, а не предупреждение.

**Что покрыто автотестами на 22.10.2026 (это не `PASS` и не готовность канала):**

- G1–G3 — логика проверок реестра: `apps/api/test/migration-inventory.test.ts` (пустой список
  ошибок на корректном реестре — стр. 179; конфликты — стр. 146–151).
- G2/G4/G5 — модель допуска и плана: `go/no-go` и план возврата в `apps/api/src/migration/cutover.ts`,
  тесты `apps/api/test/cutover.test.ts`; сверка пилота — `apps/api/src/migration/pilot.ts`,
  тесты `apps/api/test/pilot.test.ts` (единственный владелец отправки — стр. 140, 189).
- Ни один канал не переключался: реального прогона по этому документу не было, все критерии
  остаются `NOT RUN` до заполнения экземпляра для конкретного канала.

| ID | Критерий | Что проверяется | Доказательство | Кто подписывает |
|---|---|---|---|---|
| G1 | Реестр заполнен | Для активного production-подключения известны: владелец, режим, актив, получение, отправка, CRM-проекция. Нет `UNKNOWN` в критичных полях | Отчёт `validateStoredInventory` без ошибок + подтверждение владельца канала | Технический руководитель, владелец канала |
| G2 | Один владелец отправки | На один актив приходится ровно один активный отправитель. Wazzup остановлен для этого актива **или** новый контур не имеет права отправки | Настройки Wazzup (обезличенный скриншот), флаги нового контура, письменное подтверждение всех владельцев автоматизаций и очередей | Эксплуатация, владелец канала |
| G3 | Один получатель входящих | На актив подписан ровно один получатель событий. Нет одновременных webhook и polling, нет второго сервера/бота, перехватывающего события | Настройки провайдера/кабинета, проверка подписки, тестовое входящее | Технический руководитель |
| G4 | Возврат проверен | Репетиция возврата на тестовом активе выполнена, старая конфигурация восстанавливается, время возврата измерено | Протокол репетиции `ops/runbooks/channel-cutover.ru.md` со статусами `PASS`, фактическое время | Эксплуатация, технический руководитель |
| G5 | Пилот пройден | Параллельный пилот завершён: потери, дубли и расхождения объяснены, необъяснённых нет | Отчёт `docs/migration/parallel-pilot.ru.md` с обезличенными счётчиками | Технический руководитель, владелец канала |
| G6 | Владение и доступы | Владелец аккаунта/номера/бота/сообщества подтверждён. Есть доступ к восстановлению и смене настроек. Секреты — в защищённом хранилище, не в Git | Запись в защищённом хранилище, подтверждение владельца, план ротации | Владелец канала, эксплуатация |
| G7 | CRM-связи проверены | На тестовом контакте и тестовой сделке проверено создание/связывание, автор исходящего, отсутствие дублей. Правила поиска контакта и сделки зафиксированы | Обезличенный протокол проверки CRM, ID тестовых сущностей в защищённом хранилище | Владелец CRM |
| G8 | История и медиа решены | Решено, что переносится, что остаётся в старом контуре, сколько живут старые ссылки. Медиа не зависит от единственной временной ссылки | Решение владельца канала + проверка открытия тестовой выборки файлов | Владелец канала, технический руководитель |
| G9 | Незавершённые действия разобраны | Очереди отправки пусты или владелец каждой известен. `pending`/`in-flight`/`unknown` перечислены, порядок ручного разбора назначен. Слепой повтор запрещён | Реестр незавершённых действий, назначенный ответственный | Эксплуатация |
| G10 | Мониторинг и дежурство | Health/readiness, алерты, журнал ошибок и дежурный на окно переключения назначены. Есть понятный признак «канал не работает» | Ссылка на дашборд/алерт, имя дежурного, время наблюдения | Эксплуатация |
| G11 | Люди и коммуникация | Операторы знают, где отвечать после переключения, что делать при сбое и куда сообщать. Клиентам не отправляется массовое уведомление без отдельного решения | Инструкция для операторов, список участников, подтверждение руководителя | Владелец канала, эксплуатация |
| G12 | Пороги и окно согласованы | Численно согласованы: допустимый перерыв, порог потерь/дублей/задержки, время наблюдения, момент возврата | Заполненный протокол окна и порогов | Владелец канала, эксплуатация |
| G13 | Правовые и провайдерские ограничения | Проверены правила канала: шаблоны, согласие клиента, 24-часовое окно, ограничения API. Нет обещаний, которые провайдер не подтверждает | Ссылка на правила провайдера и подтверждение, что сценарий им соответствует | Владелец канала |
| G14 | Нет посторонних изменений | В окно переключения не меняются другие подключения, боты, автоматы и интеграции. Изменение несогласованного подключения — стоп | Список изменений окна, подтверждение каждого владельца | Эксплуатация |

### B1. WhatsApp

## Часть C. Стоп-условия

Срабатывание **любого** пункта означает `NO-GO` для этого канала. Уже начатое переключение переводится в режим остановки: запрет новых эффектов, сохранение состояния, решение по возврату.

| ID | Стоп-условие |
|---|---|
| S1 | Хотя бы одно критичное поле реестра — `UNKNOWN`: владелец, режим, актив, получение, отправка, CRM-проекция |
| S2 | На один актив приходится два активных отправителя (Wazzup и новый контур, два бота, две интеграции) |
| S3 | На один актив приходится два получателя входящих или одновременно webhook и polling |
| S4 | Возврат не проверен на тестовом активе или его невозможно выполнить в согласованное время |
| S5 | У канала нет ответственного человека; владелец аккаунта/номера/сообщества не подтверждён |
| S6 | Провайдер не допускает второго получателя, а режим раздельных тестовых активов недоступен |
| S7 | В пилоте есть необъяснённые расхождения, потери или дубли |
| S8 | Есть неразобранные `pending`/`in-flight`/`unknown` отправки, и не назначен ответственный за ручной разбор |
| S9 | Нет доступа к смене настроек, восстановлению или перевыпуску ключей |
| S10 | Нет мониторинга, алертов или дежурного на окно переключения |
| S11 | Превышены согласованные пороги потерь, дублей, задержки или перерыва |
| S12 | В окне переключения изменилось несогласованное подключение, бот, автомат или интеграция |
| S13 | Нарушены правила провайдера: нет шаблонов, нет согласия клиента, сценарий вне допустимого окна |
| S14 | Не выдержано согласованное время наблюдения |
| S15 | В CRM появились дубли, потеряны связи контакта/сделки или сломано авторство исходящего |
| S16 | Операторы не знают, где отвечать, или нет резервного способа работы при сбое |

`STOP` не означает удаление данных, отзыв номера или уничтожение истории. Сначала фиксируются состояние, очередь и неопределённые отправки; затем выполняется согласованная процедура возврата.
