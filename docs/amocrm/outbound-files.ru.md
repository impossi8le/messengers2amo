# Фото и файлы amoCRM → Telegram

Обработчик native Chats webhook v2 принимает исходящие `picture` и `file`,
сохраняет команду в существующую очередь `crm.reply` и передаёт оригинальные
байты через Telegram `sendPhoto` / `sendDocument`. Подпись становится caption;
пустая подпись допустима. Имя документа сохраняется. Текстовый путь не меняется.

Поля webhook соответствуют [официальному формату amoCRM](https://www.amocrm.ru/developers/content/chats/chat-webhooks):
`message.type`, `media`, `text`, `file_name`, `file_size`. Отсутствующий или нулевой
размер означает неизвестный размер и не отменяет проверку фактически скачанных
байтов. Отклонённое вложение не заменяется отправкой одного текста подписи.

## Подготовка и доставка

Ссылка принимается только по HTTPS с известных источников amoCRM. Загрузка
ограничена размером и временем; OAuth передаётся только Drive, при переходе на
CDN не пересылается. Токены и временные ссылки не попадают в публичную историю
сообщений. Фото ограничены 10 MiB, документы — 20 MiB, подпись — 1024 символами.
Для фото проверяется сигнатура JPEG/PNG/WebP. GIF/видео/аудио и другие типы
в этот native путь не подключены.

Миграция 020 добавляет `amocrm_outbound_files`: состояние подготовки хранится
отдельно для каждой операции. Файл архивируется через Files API и связывается
с существующей сделкой, затем проверяется по размеру и SHA256 перед Telegram.
Если в локальной связи нет lead_id, допускается только одна найденная открытая
сделка контакта; новые контакты и сделки этот обработчик не создаёт.

После файлового I/O worker повторно проверяет права, текущее подключение,
эпоху, lease/fence, срок команды, адресата и область пилота. Идемпотентность
команды сохраняется. Успешная отправка записывает вложение в историю.
Неопределённый результат Telegram остаётся `unknown` и автоматически не
повторяется; неопределённая загрузка в Files API также не загружается повторно
вслепую. Обычная отправка по-прежнему зависит от существующих переключателей
OUTBOUND_ENABLED / send_enabled; наличие реализации не включает её глобально.

## Проверка 29.10.2026

API typecheck и полный набор изолированного release-кандидата прошли: 616/616.
Проверены native webhook picture/file, точные байты, подписи и имена,
идемпотентность, отзыв доступа во время подготовки, неопределённые ответы
Telegram/Files API, ограничения размера и безопасные переходы загрузки.

Установлена сборка `20261029-outmedia-53beb00`, схема 20. Реальные ограниченные
пилоты передали уже сохранённые синтетические файлы amoCRM в два тестовых
Telegram-диалога. Подтверждены фото provider 32/34 и TXT provider 31/35.
Оба TXT скачаны из Telegram с совпадением SHA256; Telegram перекодировал фото.
Первая отдельная попытка TXT второму аккаунту осталась `unknown`; её состояние
не сбрасывалось, повторный успешный тест имеет отдельный ключ и CHECK2-маркер.

Это проверка серверной передачи настоящих файлов Files API, а не доказательство
полного пользовательского пути через редактор amoCRM. При проверке редактора
и вкладки «Файлы» загрузка PNG/TXT зависала до webhook; пользователь подтвердил
такое же поведение в обычном браузере. Реальный native webhook с вложением
на этот момент не получен. Вопрос передан поддержке amoCRM; полная проверка
кнопки «Отправить» остаётся незавершённой до устранения этого блокера.
