## Причина `ERR_CERT_COMMON_NAME_INVALID`

Virtual host для `messengers.example.com` в конфигурации nginx **отсутствует**. Запрос попадает в первый по порядку `server`-блок на 443, то есть в vhost `other-service.example.com`. Его сертификат содержит единственное имя `DNS:other-service.example.com`, поэтому проверка имени хоста не проходит.

Проверка: `openssl s_client -servername messengers.example.com` возвращает сертификат с `subject=CN=other-service.example.com` и `subjectAltName=DNS:other-service.example.com`. По HTTP запрос отдаёт 404 — то есть домен обслуживается, но не тем сайтом.

Исправление: отдельный `server`-блок для целевого домена и собственный сертификат только на это имя. Отключать проверку TLS, расширять сертификат `dzen` или менять чужие vhost'ы не требуется и не разрешается.

## Бюджет ресурсов

Доступно 1622 МБ RAM и 32 ГБ диска. Планируемая нагрузка одного проекта: API (≈256 МБ), воркер (≈256 МБ), PostgreSQL 18 (≈512 МБ). Итого ≈1 ГБ — помещается с запасом, но swap отсутствует, поэтому лимиты контейнеров обязательны, а при росте нагрузки потребуется либо swap, либо расширение RAM.
