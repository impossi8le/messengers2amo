# Локальный Telegram-стенд

Рабочая переписка через отдельного Telegram-бота, без amoCRM, Docker и сторонних npm-зависимостей. Нужен Node.js 24. Для быстрого локального теста используются встроенные HTTP и SQLite; это отдельный прототип, а не готовая production-платформа из основного проекта.

## Как попробовать

1. Скопируйте `.env.example` в `.env` и внесите токен отдельного тестового бота локально. Затем запустите `start.cmd` или выполните `npm start` из этой папки.
2. Откройте <http://127.0.0.1:3210>.
3. В Telegram откройте тестового бота и нажмите **Start**, затем напишите ему.
4. Выберите появившийся диалог в браузере и ответьте. Enter отправляет, Shift+Enter добавляет строку.

Токен хранится только в вашем локальном `.env`. Он не передается браузеру, не выводится в API и не включается в Git. Публичная установка webhook не нужна: используется long polling.

Интерфейс обновляется примерно раз в три секунды. Приложение слушает только `127.0.0.1`; оно рассчитано на одного оператора на этом компьютере. Удаленный доступ и многопользовательская авторизация не реализованы.

## Демо без Telegram

`demo.cmd` открывает отдельный режим на <http://127.0.0.1:3211>. Там есть искусственные диалоги и кнопка моделирования входящего; ответы остаются только в демобазе. Надпись «Демо · без отправки» означает, что сообщения не идут в Telegram. Рабочая и демоверсия разделены по области данных.

## Что реализовано

- Получение личных сообщений и их текстовых правок от Telegram.
- Список диалогов, поиск, история и ответы текстом до 4096 символов.
- Сохранение истории, offset и состояний в локальной SQLite.
- Дедупликация обновлений и команд отправки.
- Счетчик входящих, ожидающих ответа: прочтение не снимает ожидание; ответ покрывает сохраненный снимок, а не новые сообщения, пришедшие во время набора.
- Достоверные состояния отправки: отправлено, ошибка, неизвестный результат; таймаут не запускает автоматический повтор.
- Проверка webhook перед polling: существующая настройка не удаляется и не перезаписывается.

Подтверждение отправки API не доказывает прочтение клиентом. Вложения отображаются текстовым обозначением; загрузка, просмотр и отправка файлов, группы, личные Telegram-аккаунты, amoCRM, распределение между менеджерами и остальные каналы не входят в эту поставку.

## Если чат не появляется

Проверьте, что открыта версия на **3210**, а сообщение отправлено самому боту в приложении Telegram. Бот не получает переписку вашего личного аккаунта. Состояние подключения и объяснение ошибки показаны вверху страницы.

Если обнаружен webhook, приложение останавливает polling вместо изменения настройки. Если токен используется другим poller, Telegram может вернуть конфликт; остановите вторую копию стенда. Не запускайте две рабочие копии с одним токеном.

При неизвестном результате сначала проверьте историю и Telegram. Повторное нажатие — новая явная попытка и может создать дубль, если первое сообщение уже дошло.

## Данные и остановка

Данные: `data/telegram.sqlite`, демоданные: `data/demo.sqlite`. Логи фонового запуска: `logs/`. Каталоги и `.env` исключены из Git. Для сохранения истории не удаляйте `data/`.

Обычный запуск из `start.cmd` останавливается Ctrl+C. Если порт занят, сначала закройте существующую копию; не запускайте новый poller на другом порту с тем же токеном. После перезапуска незавершенная отправка становится «результат неизвестен» и не повторяется автоматически.

## Проверки

`npm test` запускает тесты встроенным Node test runner с реальной SQLite и подменой только внешней границы Telegram. Тесты не используют локальный токен и не отправляют сообщения реальным получателям.

Документация API: [Telegram Bot API](https://core.telegram.org/bots/api). План production-проекта находится в [каталоге документации](../docs/stack-and-parallel-rollout.ru.md); локальный стенд не требует его полной инфраструктуры.
