# Участие в разработке

Изменения предлагайте через issue и pull request. Опишите сценарий пользователя, ожидаемое поведение и фактический результат. Используйте синтетические примеры без переписки, токенов и данных клиентов.

Для разработки нужен Node.js 24; для тестов API и доменной БД — отдельная PostgreSQL 18. Устанавливайте зависимости через `npm ci` внутри затронутого приложения или пакета. Общего корневого npm workspace в проекте нет.

Перед pull request выполните относящиеся к изменению тесты и проверку типов; для веб-интерфейса — также `npm run build`. Укажите команды, результаты и пропущенные проверки. Работоспособность внешних каналов подтверждается отдельным сквозным прогоном с тестовыми доступами.

При изменении обработки сообщений учитывайте повторную доставку, конкурирующих обработчиков, неопределённый результат отправки и восстановление после перезапуска. Подробнее — [правила разработки](docs/development.ru.md).

Не добавляйте реальные `.env`, ключи, сессии, базы и диагностические выгрузки. Для настройки окружения используйте `.env.example`.
